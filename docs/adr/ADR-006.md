# ADR-006: Preservación del prototipo y raíz greenfield separada

- Estado: **ACEPTADA — autorizada por el humano**
- Fecha: 2026-08-28

## Contexto

El remoto `RenanGomez/superRestaurant` conserva un prototipo previo en
`origin/main` y `origin/master`. Esa historia incluye miles de rutas de
`node_modules` versionadas y no contiene una licencia explícita para el código
propio. Integrarla automáticamente en la modernización arrastraría artefactos,
mezclaría arquitecturas y haría difícil revisar el nuevo producto.

El monorepo moderno se construyó localmente como una historia sin padre. El
humano autorizó crear y publicar una rama separada para conservar todo el
avance y poder recuperarlo en otro equipo.

## Decisión

- Preservar `origin/main` y `origin/master` sin merge, rebase, limpieza ni
  reescritura.
- Mantener la modernización como raíz greenfield independiente en
  `codex/modernizacion-fase0` y, por autorización humana posterior, adoptarla
  como contenido de `main` mediante un merge de historias con estrategia
  `ours`.
- No copiar código del prototipo hasta contar con autorización/licencia escrita
  del titular y una tarea de migración explícita.
- Usar commits convencionales y ramas pequeñas a partir de la rama greenfield.
- No reescribir ni forzar ramas remotas. Integraciones futuras requieren
  autorización humana y deben preservar el historial recuperable.

## Evidencia

- Primer commit greenfield: `ceaffcb` (`feat: establish modern POS foundation`).
- Rama publicada: `origin/codex/modernizacion-fase0`.
- Merge de adopción: `f9f4428` (`chore: adopt greenfield foundation on main`).
- El push HTTPS actualizó `main` por fast-forward, sin `force-push`. Su árbol es
  idéntico al de la rama greenfield; la historia anterior permanece como el
  segundo padre del merge y `origin/master` no fue modificada.
- `.gitignore` excluye secretos, certificados, dependencias, builds, cobertura,
  caches y artefactos temporales.

## Recuperación en otro equipo

```sh
git clone https://github.com/RenanGomez/superRestaurant.git
cd superRestaurant
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

## Consecuencias

La modernización tiene un punto de recuperación remoto y es el contenido de la
rama principal sin contaminar su árbol con el prototipo. La comparación o
migración futura del legado debe hacerse de forma dirigida y conservar
atribución/licencia. El historial previo sigue recuperable desde el segundo
padre de `f9f4428` y desde `origin/master`.
