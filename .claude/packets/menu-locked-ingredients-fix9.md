## Hallazgos a corregir
1. **P1 migración ~619 y ~641 (y el test en `menu_locked_ingredients_invariants.sql` ~564 y ~582)**: con productores antiguos, `excludableIngredientIds = []` significaba «nada se puede quitar». El filtro `cardinality(...) > 0` evita derivar bloqueos y deja todo removible: invierte la semántica. Debe quedar: cuando `lockedIngredientOptionIds` **no viene** en el payload (productor antiguo) la derivación se ejecuta siempre; con etiquetas vacías se bloquean **todas** las opciones del grupo de ingredientes; lo mismo en el backfill de la migración para filas existentes con `fraction_excludable_ingredient_ids = '{}'` y grupo de ingredientes presente. Corrige el test para reflejarlo y añade casos producto y variante.
2. **P2 `product-sheet.tsx:110-120` y `packages/domain/src/menu.ts:568-571`**: se mezclan opciones UUID actuales con todas las etiquetas legadas; en un catálogo migrado aparecen dos chips «Sin Cebolla» y las capturas nuevas siguen generando etiquetas. Debe quedar: para captura y precio actual, exclusivamente «opciones activas del grupo − bloqueadas» (ids); las etiquetas sólo se usan para leer/proyectar snapshots históricos. Ajusta `line-halves.ts` si valida contra etiquetas; tests de dominio y web.
3. **P2 verificador + test (`run-menu-locked-ingredients-schema-verification.ts:125,133`; test ~96-122)**: el runner aplica la migración y luego el test simula el backfill a mano, así que el backfill real no se prueba ni el caso de etiquetas no mapeadas/ambiguas, ni que un snapshot confirmado antes quede byte a byte igual. Debe quedar: el runner siembra fixtures legados (producto con etiquetas mapeables, uno con etiqueta sin opción, uno con nombres duplicados, uno con `[]`, y una orden confirmada con mitades) **antes** de aplicar la candidata, aplica la candidata y después comprueba `fraction_locked_ingredient_option_ids` por caso y que el snapshot de la orden no cambió (comparación `jsonb` exacta). Sigue el patrón del runner de grupos compartidos (que ya siembra antes de migrar).
4. **P2 `dryrun-menu-locked-ingredients.ts:40,51,79`**: el dry-run excluye filas sin grupo y fracciones deshabilitadas, así que `fracciones_sin_grupo_ingredientes` siempre es 0. Debe partir de todas las filas con `cardinality(fraction_excludable_ingredient_ids) > 0` y reportar `fraction_extra_group_id is null` como categoría propia, igual que la consulta del reporte de investigación.
