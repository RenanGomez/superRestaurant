# web-e2e-harness · arnés E2E con Playwright (escritorio, móvil, offline) + crawl exhaustivo del DOM + buttonmash

## Tarea
web-e2e-harness · capa L1 `implementer-claude` · **nivel C** (sólo `apps/web`, tooling de pruebas; no toca `src/`) · riesgo bajo. Rama `claude/web-e2e-harness` desde `main`.

## Objetivo
Que `apps/web` tenga una suite E2E ejecutable contra los servidores locales ya levantados (web `http://localhost:8082`, API `http://localhost:3000`, ambos responden 200 ahora mismo) que: (a) recorra todas las rutas autenticadas en escritorio y en perfil móvil, (b) pulse de forma segura todos los elementos interactivos de cada ruta y reporte errores JS/5xx, (c) documente el comportamiento al cortar la red, y (d) deje configurado `buttonmash` como monkey tester exhaustivo. La sesión la aporta un humano con un login manual en Chrome; ningún script escribe credenciales.

## Decisiones ya tomadas (no reabrir)
- Playwright `@playwright/test@1.64.1` y `buttonmash@0.3.1` como devDependencies de `apps/web` (ambos ya están en el store de pnpm; `pnpm add -D ... --offline` funciona). Node 24 nativo soporta `node archivo.ts` (type stripping), no instalar `tsx`.
- Navegador: el Chrome instalado (`channel: "chrome"`). **No descargar navegadores de Playwright** (`playwright install` queda documentado como paso opcional del humano para buttonmash, que no soporta `channel`).
- Autenticación: `e2e/save-auth.ts` abre Chrome con `headless:false` en `/login`, espera `waitForURL` a `/app*` hasta 10 min, y guarda `storageState` en `apps/web/playwright/.auth/user.json` (gitignored). `playwright.config.ts` usa ese archivo sólo si existe (`fs.existsSync`); si no existe, los tests autenticados fallan con el mensaje «Sin sesión: ejecuta pnpm e2e:auth».
- Proyectos Playwright: `desktop` (Desktop Chrome, 1366×800), `mobile` (`devices["Pixel 7"]`, channel chrome), `offline` (Desktop Chrome, `grep: /@offline/`). `workers: 1`, `fullyParallel: false`, `retries: 0`, reporter `list` + `html` en `playwright-report/` (`open: "never"`), `trace: "retain-on-failure"`, `screenshot: "only-on-failure"`, `locale: "es-MX"`, `timezoneId: "America/Mexico_City"`.
- Rutas (archivo `e2e/routes.ts`, exportar `APP_ROUTES` y `PUBLIC_ROUTES` con `{ path, label }`): autenticadas `/app`, `/app/tables`, `/app/menu`, `/app/caja`, `/app/orders`, `/app/deliveries`, `/app/customers`, `/app/capture`, `/app/delivery-zones`, `/app/reports/day`, `/app/system-admin/restaurants`; públicas `/login`, `/reset-password`. (Fuente: `src/app/app/app-nav.tsx` y los `page.tsx` bajo `src/app/app`.)

## Archivos a crear (todos en `apps/web/`)
1. `playwright.config.ts` — lo anterior. `testDir: "./e2e"`, `outputDir: "./test-results"`, `timeout: 90_000`, `baseURL` desde `E2E_BASE_URL` o `http://localhost:8082`.
2. `e2e/routes.ts`.
3. `e2e/save-auth.ts` — login manual descrito arriba; crea la carpeta con `mkdirSync({recursive:true})`; imprime instrucciones en español; nunca imprime cookies.
4. `e2e/helpers.ts` — `attachDiagnostics(page)`: acumula `pageerror`, `console` tipo `error`, respuestas con `status >= 500` y requests fallidas (`requestfailed`, ignorando `net::ERR_ABORTED` y, en el proyecto offline, `ERR_INTERNET_DISCONNECTED`); devuelve `{ pageErrors, consoleErrors, serverErrors, failedRequests }`. `expectAuthenticated(page, path)`: si la URL final empieza por `/login`, `test.fail`/throw con «Sin sesión: ejecuta pnpm e2e:auth». `hasNextErrorOverlay(page)`: `nextjs-portal` presente o texto «Application error» / «Unhandled Runtime Error». `DESTRUCTIVE` regex (sin distinguir mayúsculas ni acentos) con: eliminar, borrar, quitar, cancelar, cerrar sesión, salir, logout, cobrar, pagar, confirmar, publicar, enviar a cocina, guardar, crear, nueva, nuevo, abrir cuenta, abrir turno, cerrar caja, cerrar turno, sin venta, transferir, desactivar, asignar, marcar, imprimir, subir, convertir, reintentar.
5. `e2e/smoke.spec.ts` — un `test` por ruta de `APP_ROUTES`: `goto`, `expectAuthenticated`, esperar `networkidle` (con catch), `expect` sin overlay de error, `expect.soft` listas de diagnóstico vacías (adjuntar el JSON con `testInfo.attach`), adjuntar screenshot de página completa. Un `describe` `@public` con `test.use({ storageState: { cookies: [], origins: [] } })` para `PUBLIC_ROUTES`: carga 200, sin overlay, sin pageerror. En el `/app*` no autenticado debe redirigir a `/login` (test `@public` adicional).
6. `e2e/dom-exhaustive.spec.ts` — un `test` por ruta de `APP_ROUTES` con `test.setTimeout(10 * 60_000)`: tras `goto` y `expectAuthenticated`, enumerar con el selector `button, a[href], [role="button"], [role="tab"], [role="menuitem"], [role="option"], summary, input:not([type="hidden"]), select, textarea`, visibles y habilitados; tope `E2E_MAX_ELEMENTS` (env, default 150). Para cada índice i: re-consultar el locator `.nth(i)` (el DOM cambia), leer `tagName`, nombre accesible (`aria-label`, `innerText` recortado a 60, `name`, `placeholder`) y `href`; **saltar** si el nombre o el href casan con `DESTRUCTIVE`, si el `href` es de otro origen o contiene `/logout`, `mailto:`, `tel:`, o si es `input[type=file]`. Si es `input`/`textarea`: `focus` + `fill` de un valor inocuo según `type` (texto «prueba e2e», number «1», email «e2e@example.com», date hoy) y luego `fill("")`/restaurar; checkbox/radio: `click` dos veces. Resto: `click({ timeout: 3_000, noWaitAfter: true })`, `waitForTimeout(300)`, `keyboard.press("Escape")`; si la URL cambió, registrar `navigatedTo` y volver con `goto(ruta)`; capturar excepciones del click como `result: "error"` sin abortar el test. Registro por elemento `{ route, index, tag, name, href, result: "clicked"|"filled"|"skipped"|"error", reason?, navigatedTo?, pageErrorsAfter: number }`. Al final de cada ruta: `expect.soft(pageErrors).toEqual([])`, `expect.soft(serverErrors).toEqual([])`, sin overlay; escribir `e2e-report/dom-coverage-<project>.json` (acumulativo por proyecto, `mkdirSync`) y adjuntar. Resumen en consola: encontrados/pulsados/saltados/errores por ruta.
7. `e2e/offline.spec.ts` — tag `@offline` en el título. Por ruta: `goto` online, `expectAuthenticated`, `context.setOffline(true)`, pulsar el primer enlace del `nav[aria-label="Navegación principal"]` cuyo `href` sea distinto de la ruta actual, `waitForTimeout(3_000)`, registrar `{ route, pageErrors, overlay, bodyTextSnippet (300 chars), url }`, `setOffline(false)`, `reload()` y comprobar que la ruta vuelve a cargar sin overlay. Sólo `expect.soft(pageErrors).toEqual([])` y `expect(sin overlay tras reconectar)`; el resto es informativo y va a `e2e-report/offline-<project>.json`. Comentario de cabecera: el web no tiene soporte offline todavía (Fase 3 del plan); esta prueba documenta el comportamiento actual.
8. `buttonmash.config.json` (raíz de `apps/web`; ejecutar antes `pnpm exec buttonmash init` para conocer el esquema real y ajustar las claves): `target` `http://localhost:8082/app`; `auth.storageState` `playwright/.auth/user.json`; `browser` `chromium`; `guardrails.destructive.extraVerbs` = la lista en español de `DESTRUCTIVE`; `guardrails.blockedPathPatterns` y `excludePaths`: `/login`, `/logout`, `/reset-password`, `/app/system-admin`; `guardrails.includePaths`: `^/app`; `budget.maxPages` 40; `explore.forms.enabled` false; `report.formats` json,html; `out` `buttonmash-report`.
9. `tsconfig.e2e.json` — `extends ./tsconfig.json`, `include: ["e2e/**/*.ts", "playwright.config.ts"]`, `exclude` vacío, `noEmit: true`, sin `plugins` de next.
10. `package.json` scripts: `"e2e:auth": "node e2e/save-auth.ts"`, `"e2e": "playwright test --project desktop"`, `"e2e:mobile": "playwright test --project mobile"`, `"e2e:offline": "playwright test --project offline"`, `"e2e:all": "playwright test"`, `"e2e:typecheck": "tsc --noEmit --project tsconfig.e2e.json"`, `"e2e:report": "playwright show-report"`, `"e2e:mash": "buttonmash run --headed --formats json,html --out buttonmash-report"`, `"e2e:mash:dry": "buttonmash run --dry-run --formats json,html --out buttonmash-report"`.
11. `.gitignore` de la raíz: añadir `apps/web/playwright/.auth/`, `apps/web/playwright-report/`, `apps/web/test-results/`, `apps/web/buttonmash-report/`, `apps/web/e2e-report/`.
12. `apps/web/e2e/README.md` (≤ 40 líneas, español): cómo levantar servidores (`tools/agentic/local-servers/start-local.bat`), `pnpm e2e:auth`, qué corre cada script, qué significa cada reporte, y que buttonmash requiere una vez `pnpm exec playwright install chromium` (descarga ~170 MB, decisión del humano).
